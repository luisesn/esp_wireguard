# Host-side crypto tests

Tests `src/crypto/refc` (BLAKE2s, X25519, ChaCha20-Poly1305 AEAD) on the
host — a plain `gcc` build, no ESP-IDF, no hardware. This is Task #6 from
`CHANGES-fork.md`.

Correctness is checked against independent, well-established
implementations, not against hand-copied constants:

- BLAKE2s: Python's `hashlib.blake2s` (stdlib), unkeyed and keyed, several
  message lengths, both the all-in-one and the streaming (init/update/final)
  API.
- X25519: the Python `cryptography` package (OpenSSL-backed) — both plain
  scalar-times-basepoint and full two-sided Diffie-Hellman (checking that
  both sides derive the same shared secret, and that it matches the
  reference).
- ChaCha20-Poly1305 AEAD, in the 64-bit-counter nonce convention this
  codebase actually uses (`nonce` = 4 zero bytes || 64-bit LE counter, per
  `wireguard-platform.h`'s calling convention): cross-checked against
  `cryptography`'s standard RFC 7539 AEAD built with that same 12-byte
  nonce. Also checks that decryption of a tampered ciphertext is rejected.

`vectors.h` is generated by `gen_vectors.py` and checked in, so running the
tests doesn't require Python or the `cryptography` package — only
regenerating it does.

## Usage

```sh
make check        # build and run
make asan         # build and run with ASan+UBSan
make vectors       # regenerate vectors.h (needs: pip install cryptography)
```

## Scope

This exercises the crypto primitives in isolation, not the full WireGuard
handshake state machine. It does not cover: TAI64N timestamp
source/monotonicity, cookie-reply-under-load behavior, or fuzzing of the
packet parser — those are separate, still-open Phase 3 items noted in
`CHANGES-fork.md`.
